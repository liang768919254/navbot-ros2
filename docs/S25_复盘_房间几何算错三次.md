## 二、我错了三次，错法一模一样

### 第 1 次：虚构了一条「0.6 m 窄道」

动笔写 `nav_patrol.py` 时，我脑子里有个笃定的印象：
"这个房间有个 0.6 m 的窄通道考点，就在两块隔板之间"。

于是设了 `(0.70,-0.10) → (0.70,1.30)` 两个点，还写了段注释夸自己：
"原先想用 (0.90,-0.60)，但那里距 partition_short 只有 0.250，属于设了也到不了的陷阱点。"

实际算出来：
- 这两个点净空 0.450 / 0.750，**全在开阔区**
- 它们中间那条"窄道"实测 0.300 m，**比车窄 10 cm，是死路**
- 就算导航报 SUCCEEDED，也**完全没测到任何窄处**

### 第 2 次：虚构了第二条「窄道 E」

发现上面错了之后，我"重新分析"地图，得出一条新结论：
"partition_short 南端 y=-1.80 到南墙 -2.45 是 0.65 m 窄道，这才是真考点"。

于是大张旗鼓地：
- 在 `room_geom.py` 里写了详细的 ASCII 拓扑图
- 算了一整套膨胀代价剖面（"非致命带宽 0.250，零代价带宽 0.150"）
- 加了 6 条自测断言锁住这些数字

**然后跑了地图逐格扫描**：

```
沿 y=-2.10 横扫：x=-2.883 → +2.917  全是空的
沿 x=0.30 竖扫：唯一的障碍是 partition_mid（y∈[0.455,0.555]）
```

`partition_short` 是块**0.1 m 宽的竖板**，只占 x∈[1.12,1.32]。
在 x=0.30 处它根本不构成障碍，那里距南墙 2.35 m。

我算的"0.65 m 缝"完全是我自己想象出来的。

### 第 3 次：虚构了「东走廊是唯一通路」

第 2 次修正时，我信誓旦旦写：
```
✓ 东走廊  1.700 m → 唯一南北通路
```
还加了断言 `chk(abs(ch_map['C 东走廊'] - 1.70) < 1e-9, ...)`，跑出来 PASS。

实际西侧也有 1.17 m 的开口，**根本不唯一**。
而且这个 1.70 的算法本身就是错的——它是用错误的 `partition_short` 东沿 `x=1.25` 减出来的，真实东沿是 1.32。

## 三、根因：把「我记得的常量」当成了真值

三次错误的共同病根，是 `room_geom.py` 开头这组常量：

```python
PARTITIONS = [
    ('partition_mid',   'h', -1.80, 0.80, 0.45, 0.55),
    ('partition_short', 'v',  1.15, 1.25, -1.80, 0.00),
]
```

这组数字**是我早前写 `loop_geom.py` 时凭印象填的**，然后：
- `loop_geom.py` 用它算航线
- `map_quality.py` 用它当墙真值
- `drive.py` 的注释里也引用它
- 我又拿它去推 Nav2 参数

**一个凭印象的数字，被四个文件引用，其中两个还给它写了"验证通过"的自测。**

直到用地图逐行扫描反推真实边界：

| 隔板 | 我写的 | 地图实测 | 差距 |
|---|---|---|---|
| `partition_mid` | x[−1.80,+0.80] y[0.45,0.55] | x[−1.78,+0.82] y≈0.50（单行） | 基本对 |
| `partition_short` | x[1.15,1.25] **y[−1.80,0.00]** | x[+1.12,+1.32] **y[−1.50,0.00]** | **y 范围错 0.3 m** |
| 第三块板 | **完全不知道** | x[−2.03,−1.73] y≈−1.50 | **漏了一整块** |

`partition_short` 的 y 范围错 0.3 m —— 这一条就足以让所有基于它的推论全盘作废。
漏掉 `partition_stub` —— 这块板恰好卡在西侧通道上，`x=-2.20` 处净空只剩 0.170。

## 四、自测也救不了前提错

这轮我在自测上花了很多力气，但一开始的自测**全是无效的**：

```python
# 第 1 版：期望值凭几何直觉写
chk(abs(clearance(0, 0) - 2.45) < 1e-6, '原点净空应 2.45（到南北墙）')
#   → FAIL，实测 0.450。原点是距 partition_mid 下沿 0.45，不是到墙
chk(abs(clearance(0, -1.0) - 1.45) < 1e-6, '应 1.45（到南墙）')
#   → FAIL，实测 1.150。到 partition_short 水平距离更近
```

**连续两次凭直觉写期望值，连续两次 FAIL。**

正确的做法是**验公式的必然性质，而不是验具体数字**：

```python
# 远离障碍方向 → 净空必须严格变大
c0 = clearance(-2.0, 0.0)     # 0.501
c1 = clearance(-2.2, 0.0)     # 0.616  ✓ 变大
# 贴着墙走 → 净空必须不增
c0 = clearance(2.0, 2.0)      # 0.450
c1 = clearance(2.2, 2.0)      # 0.450  ✓ 不增
# 净空必 <= 到任一面墙的距离（上界）
```

这些是**恒真的**，猜不错。

但更根本的教训是：**自测只能保证「代码符合我的模型」，不能保证「我的模型符合现实」。**
我的 `PARTITIONS` 常量错了，自测照样全 PASS，因为自测的期望值也来自同一个错误模型。

## 五、纠正后的做法

### 5.1 几何真值从哪来

**从地图逐行扫描反推，不从记忆里抄。**

```python
def row_spans(y):
    """扫描某一行，返回所有墙段的 (x_start, x_end)。"""
    ...

for y in [0.60, 0.55, 0.50, 0.45, 0.40, ...]:
    sp = [s for s in row_spans(y) if s[0] > -2.9 and s[1] < 2.9]  # 去掉外墙
    print('y=%+.2f  %s' % (y, sp))
```

输出直接给出真实边界，不用猜。

### 5.2 判据要分层

「能不能过」不是看缝宽 > 车宽就够了，要分三层：

| 层 | 判据 | 说明 |
|---|---|---|
| 物理 | `gap > 2 × robot_radius` | 车塞得进去 |
| 代价图 | `gap > 2 × inflation_radius` | 有零代价带，DWB 愿意走 |
| 非致命 | `gap > 2 × robot_radius` | 有 cost<253 的格，NavFn 允许规划 |

本项目缝 N：物理过（0.45>0.40）、非致命过（余 0.05）、**零代价不过**（0.45<0.50）。
所以它不是"过不去"，是"能规划但代价高，规划器会优先绕路"。

**这三层的区别之前我完全没分**，笼统地说"过不去"，导致后续推论全歪。
