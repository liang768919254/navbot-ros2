## 〇、先建立一个心智模型（最重要的第一句话）

**URDF 不是在「画图」，是在「用文字描述一棵坐标系树」。**

- 机器人 = 一堆**刚体**（link）
- 刚体之间靠**连接**（joint）串起来
- 每个连接要回答「子刚体相对父刚体，**挪了多少、转了多少**」（origin）

你写的每一行 `<origin xyz="..." rpy="..."/>`，本质都是在回答同一个问题：
**「这个部件的坐标系，相对它父部件的坐标系，位置在哪、转没转？」**

类比：乐高。每个零件是 link，两块积木怎么拼是 joint，「拼在哪个凸点上、朝哪个方向」是 origin。

## 一、两大文件格式：URDF 与 xacro

| 概念 | 是什么 | 关系 |
|---|---|---|
| **URDF** | 描述机器人结构的标准格式（Unified Robot Description Format），本质是 XML | 最终给 ROS 用的 |
| **xacro** | URDF 的「宏扩展」格式，加了变量、宏、数学表达式 | 写完用 `xacro` 命令**展开**成纯 URDF |

> 为什么要 xacro：URDF 是「死」的，左右两个轮子几乎一样却要写两遍。xacro 让你用**宏**只写一遍，靠参数区分左右。`xacro navbot.xacro` 会把宏展开成真正的 URDF 文本。

## 二、三大核心概念（整棵树的地基）

### link —— 刚体

- **定义**：一个不会变形的刚体，是最小的「零件」。
- **关键**：每个 link 自带一个**坐标系**（frame），link 的 origin 就是描述这个坐标系。
- **空 link 也合法**：`base_footprint` 没有任何几何体，它只提供一个坐标系原点——这完全合法，因为 link 的本质是「坐标系」，不是「形状」。

### joint —— 连接

- **定义**：两个 link 之间的**连接关系**，有 `parent`（父）和 `child`（子）。
- **为什么它是「平级」的、不能嵌套在 link 里**：joint 连接的是**两个** link，它天生横跨两端，不可能属于某一个 link。所以 link 和 joint 都直接挂在 `<robot>` 下，是兄弟关系。
- **有方向**：joint 只描述「child 相对 parent」，反过来不成立。树有根（root），根没有 parent。

### origin —— 位姿

- **定义**：子坐标系相对父坐标系的**位置 + 姿态**。
- **两部分**：`xyz`（平移，单位米）+ `rpy`（旋转，单位弧度）。
- **本质**：一个「坐标系变换」，把子坐标系的坐标，换算到父坐标系里。

---

## 三、坐标系（frame）与 TF 树

- **frame（坐标系）**：一个参考系，有原点 + 三个轴方向。每个 link 都有一个。
- **origin = 两个 frame 之间的变换**：把「子 frame 里的一个点」换算成「父 frame 里的坐标」。
- **TF 树**：把机器人所有 link 的 origin 连起来，就是一棵「坐标系树」。ROS 的 TF 系统靠这棵树，把任何两个坐标系互相换算。

> 这就是为什么 `base_footprint → base_link → left_wheel_link` 是一条链：`base_footprint` 是根，每个 joint 的 origin 定义了「下一级相对上一级」的变换。

## 四、link 的三个可选块

| 块 | 给谁用 | 能省吗 | 为什么 |
|---|---|---|---|
| `<visual>` | RViz 显示 | 能省 | 纯「外观」，物理不认它 |
| `<collision>` | Gazebo 碰撞检测 | 仿真必需 | 物理引擎靠它判断「撞没撞」 |
| `<inertial>` | 物理引擎算运动 | 仿真必需 | ★ 没有它，物理引擎不知道这部件多重、怎么转 |

> 为什么 visual 和 collision 常写得一模一样：因为「看着的样子」和「撞的样子」对简单几何体（box/cylinder/sphere）就是同一个形状。复杂模型才会让 collision 用简化形状（省算力）。

## 五、joint 的类型（本项目只用前两种）

| 类型 | 自由度 | 能干什么 | 本项目用在哪 |
|---|---|---|---|
| **fixed** | 0（焊死） | 完全固定，不能动 | base_joint、万向球、雷达 |
| **continuous** | 1（无限转） | 绕一个轴无限旋转，没有角度限位 | 左右驱动轮 |
| revolute | 1（有限转） | 绕轴转，但有角度限位 | 机械臂关节（本项目不用） |
| prismatic | 1（平移） | 沿轴滑动 | 推杆/滑轨（本项目不用） |

> 为什么轮子用 continuous 而不是 revolute：轮子要一直转、没有「最多转多少度」的限制，continuous 正好是「无上限旋转」。

### 配套属性（不是所有 joint 都要）

| 属性 | 什么时候要 | 什么时候不要 |
|---|---|---|
| `<axis>` | 会动的关节（continuous/revolute/prismatic），指定「绕/沿哪根轴」 | **fixed 不需要**（它不动） |
| `<limit>` | 会动的关节，指定力矩/速度上限 | **fixed 不需要** |

> 你这次在 caster（fixed）里写了 axis 和 limit，就是「给焊死的关节装了转轴」——多余。fixed joint 三样都没有：没轴、没限位、没自由度。

## 六、origin 的 xyz 与 rpy（★★ 最容易混，重点）

### xyz —— 平移

- 沿 X/Y/Z 轴各平移多少**米**。
- `xyz="0.04 0 0.05"` = 沿 X 走 4cm、沿 Z 抬 5cm。

### rpy —— 旋转

- **r**oll 绕 X 轴、**p**itch 绕 Y 轴、**y**aw 绕 Z 轴，单位**弧度**。
- `rpy="-1.5708 0 0"` = 绕 X 轴转 -π/2（-90°）。

### 最经典的例子：轮子为什么绕 X 转 -90°

圆柱的默认轴沿 **Z**（立着的）。但轮子要**横躺**着滚、轴朝 **Y**。所以绕 X 轴转 -90°，把「立着的圆柱」放倒成「横着的轮子」。

> 记忆口诀：**xyz 管「挪」，rpy 管「转」**。把「高度」写进 rpy，等于把「挪多远」填进了「转多少」的格子——这是你这次犯过的错。

## 七、两个 origin 的区别（★★ 本次踩坑的核心）

同一个 link，会遇到**两个** origin，它们回答的是**不同的问题**：

| origin | 回答的问题 | 对称几何体通常写 |
|---|---|---|
| **visual / collision 的 origin** | 这个几何体，相对**自己 link 原点**偏移了多少 | `0 0 0`（球/圆柱关于自身中心对称，中心就是原点） |
| **joint 的 origin** | 这个 link，相对**父 link**偏移了多少 | 实际位置（如 `0.04 0 0.05`） |

> 一句话：**「部件长在哪」写在 joint 里，「几何体相对自己」写在 visual/collision 里。**
> 你这次把「球心高度 -0.035」「雷达高度」写进了 visual/collision 的 origin——那是把「部件的位置」错填到了「几何体自身偏移」的格子里。球心相对球这个 link 的中心，永远是 0 0 0。

## 八、惯性张量（为什么有 6 个数，为什么不能拍脑袋）

### 它是什么

描述「质量怎么分布在刚体里」的量。质量决定「推多重」，惯性张量决定「转起来费不费劲、绕不同轴转的难易是否一样」。

### 为什么是 6 个数

惯性张量是个 3×3 矩阵，但因为对称，只剩 6 个独立值：

```
[ ixx  ixy  ixz ]
[ ixy  iyy  iyz ]
[ ixz  iyz  izz ]
```

- **对角 3 个**（ixx/iyy/izz）：绕 X/Y/Z 轴转的「转动惯量」。
- **非对角 3 个**（ixy/ixz/iyz）：叫「惯性积」，反映质量分布是否关于坐标轴**对称**。几何体对称时，这三个是 **0**。

### 为什么不能拍脑袋填 0.1

物理引擎（Gazebo）真的拿这 6 个数解运动方程。填错 = 解出一个「不合物理」的结果，表现就是车会**莫名抖动 / 突然旋转 / 一碰就飞**——而且报错完全看不出是惯性填错了。

> 公式在 `A3_URDF建模模板.md` 第五节，照公式代尺寸，别拍脑袋。

## 九、xacro 宏：三个概念别混

| 概念 | 是什么 | 代码 |
|---|---|---|
| **定义宏** | 声明「这个宏接收哪些变量」 | `<xacro:macro name="wheel" params="prefix side">` |
| **调用宏** | 传具体值，让它展开 | `<xacro:wheel prefix="left" side="1"/>` |
| **在宏里用别的宏** | 宏体内再调用另一个宏 | `<xacro:cyl_inertia m="0.15" .../>` |

> 你这次犯的错：把「要用的宏」（cyl_inertia）写进了 `params`。**params 里只放「这个宏自己接收的变量」，不是放「要用到的宏」**。「用」宏 = 在体内写 `<xacro:宏名 .../>`。

## 十、base_footprint vs base_link（工程意义）

| | `base_footprint` | `base_link` |
|---|---|---|
| 位置 | 车体在**地面的投影点**（z=0） | 车体**几何中心**（离地约 5cm） |
| 有没有形状 | 没有（空 link） | 有（底盘 box） |
| 谁用它 | Nav2 的 AMCL / 代价地图 | 建模、RViz 可视化 |

> **为什么分两个**：里程计描述的是「地面上的平面运动 (x, y, θ)」——只有三个自由度。用地面投影点做基准，三个自由度干干净净；用 base_link 会掺进一个「永远不变的高度 z」，纯属多余信息。Nav2 导航只关心「车在地面上占多大地方、朝哪」，所以它找 `base_footprint`。

## 十一、一页速查：易混淆对照表

| 容易混的 | 区别 |
|---|---|
| link vs joint | link = 刚体（有形状），joint = 连接（跨两个 link），平级不嵌套 |
| xyz vs rpy | xyz = 平移（米），rpy = 旋转（弧度） |
| visual/collision origin vs joint origin | 前者 = 几何体相对自己 link 原点（对称体 0 0 0），后者 = link 相对父 link |
| `_link` vs `_joint` 后缀 | link 名用 `_link`，joint 名用 `_joint` |
| fixed vs continuous | fixed 焊死不能动，continuous 无限旋转（轮子用） |
| 对角 vs 非对角惯性 | 对角 = 绕轴转动惯量，非对角 = 对称性（对称体为 0） |
| 宏定义 vs 宏调用 vs 宏参数 | 定义声明变量，调用传值，params 只放变量不放宏 |

## 十二、用一句话串起来

> **机器人 = 一棵坐标系树；link 是节点，joint 是边，origin 是边上写的「怎么从父到子」。**
> 你写 URDF，就是在**口述这棵树**：有哪些刚体、谁连谁、每个连接挪了多少转了多少、每个刚体多重惯性多大。
