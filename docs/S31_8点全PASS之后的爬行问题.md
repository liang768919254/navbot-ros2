## 四、几何分析：它到底在爬什么

### 4.1 缝 S 的北侧入口被膨胀封死

沿 `y = -1.60 ... -2.00` 逐点扫代价（`##` = 致命）：

```
  y=-1.60  x1.5:## x1.4:## x1.3:## x1.2:## x1.1:## x1.0:##
  y=-1.70  x1.5:## x1.4:## x1.3:## x1.2:## x1.1:## x1.0:##
  y=-1.75  x1.5:## x1.4:## x1.3:## x1.2:## x1.1:## x1.0:##
  y=-1.80  x1.5:## x1.4:## x1.3:## x1.2:## x1.1:## x1.0:##
  y=-1.85  x1.5:## x1.4:## x1.3:## x1.2:## x1.1:## x1.0:##
  y=-1.90  x1.5:23 x1.4:## x1.3:## x1.2:## x1.1:## x1.0:##
  y=-2.00  x1.5:.. x1.4:.. x1.3:24 x1.2:24 x1.1:24 x1.0:..
```

**`y >= -1.90` 完全封死，必须退到 `y = -2.00` 才有通道。**

也就是说：从 `(2.13, -1.40)` 到 `(0.00, -2.00)`，几何上是一条**直角路线**
——先竖直南下到 `y ≈ -2.15`，再转向西。

### 4.2 但 A* 给的是一条「擦边斜线」

```
直角绕行长度 = 0.98 + 1.50 = 2.48 m
A* 实测段长 =              2.41 m
直线距离    =              2.21 m
```

A\* 的 2.41 m 介于两者之间，绕行系数只有 **1.09**。
`--plan` 那一栏写着：**最小净空 0.225 m**。

净空 0.225 意味着**全程贴着膨胀边界 5 mm 走**——`inflation_radius` 是 0.22，
它选的路线离零代价线只差 5 mm。

```
沿 (2.13,-1.40)->(0,-2.00) 直线采样：
  (1.70,-1.52) 净空 0.387
  (1.49,-1.58) 净空 0.174  ← 已经小于车半径 0.20
  (1.28,-1.64) 净空 0.000  ← 直接顶在短板南端
  (1.06,-1.70) 净空 0.052
```

**规划路径擦着短板南端过，余量 0。** DWB 只能沿着这条线一点点蹭。

### 4.3 为什么 DWB 不肯离开那条线

这是本轮的核心。看 `base_obstacle.cpp` 源码：

```cpp
double BaseObstacleCritic::scorePose(const geometry_msgs::msg::Pose2D & pose) {
  unsigned char cost = costmap_->getCost(cell_x, cell_y);
  if (!isValidCost(cost)) {
    throw dwb_core::IllegalTrajectoryException(name_, "Trajectory Hits Obstacle.");
  }
  return cost;                     // ← 返回【原始代价 0..252】，不归一化
}

bool BaseObstacleCritic::isValidCost(const unsigned char cost) {
  return cost != LETHAL_OBSTACLE          // 254
      && cost != INSCRIBED_INFLATED_OBSTACLE  // 253
      && cost != NO_INFORMATION;          // 255
}
```

**两个此前理解错的点：**

1. **253/254 不参与打分，是直接 `throw` 淘汰轨迹。**
   我在 S28 的注释里写「253 的代价乘 0.02 才 5.06 分」——**这句是错的**，
   253 根本进不了打分环节。
2. **进入打分的 cost 是 0..252 的原始值，不归一化。**

于是量级账（`scale = 0.1` 时）：

| 项 | 分数 |
|---|---|
| 贴墙（净空 0.210，cost 240）罚 | 240 × 0.1 = **24.0** |
| `PathAlign` 偏离 0.05 m 罚 | 32 × (0.05/0.25) = **6.4** |
| `PathAlign` 偏离 0.10 m 罚 | **12.8** |

**贴墙省 24 分，离开 10 cm 花 12.8 分 → 净赚 11.2 分。**

分差太小了。而离开那条线还要冒「轨迹末端压进 253 被淘汰」的风险。
**DWB 的理性选择就是：贴着膨胀边界、以极低速爬。**

## 五、试过但无效的方向（都算过账）

### 5.1 降 `cost_scaling_factor`：无效

直觉是「让膨胀层形成缓坡，别那么陡」。但 `inflation_radius 0.22 - robot_radius 0.20 = 0.02 m`：

| k | 净空 0.205 | 0.210 | 0.215 | 0.220 |
|---|---|---|---|---|
| 5.0 | 247 | 241 | 235 | **0** |
| 3.0 | 249 | 246 | 242 | **0** |
| 1.0 | 252 | 250 | 249 | **0** |

**2 厘米的带宽里，无论 k 取什么，都是一道陡台阶。** 降 k 只是让台阶更「方」（更接近 253），反而更糟。

### 5.2 加大 `inflation_radius`：被缝 N 卡死

想要 ≥ 5 cm 的缓坡需要 `R >= 0.25`。但：

| 缝 | 缝宽 | `2R` 上限 | R=0.25 是否可行 |
|---|---|---|---|
| 缝 N | 0.450 | 0.225 | **✗ 超过上限** |
| 缝 S | 0.655 | 0.328 | ✓ |
| 缝 W | 1.167 | 0.584 | ✓ |

R 已经是 0.22，离上限 0.225 只剩 **5 mm**。这是 S27 花一整轮换来的结论，不能再动。

### 5.3 开 `sum_scores`：会帮倒忙

`sum_scores = true` 会把整条轨迹的代价累加，量级变成 `~sim_time × freq` 倍。
后果是「远处有个障碍就否决一条本来安全的轨迹」——窄缝场景反而更容易卡。
保持 `false`。

## 六、真正的修法：`BaseObstacle.scale` 0.1 → 0.5

### 账

| | scale = 0.1 | scale = 0.5 |
|---|---|---|
| 贴墙（cost 240）罚 | 24.0 | **120.0** |
| 偏 10 cm 花 | 12.8 | 12.8 |
| **净收益** | +11.2（太小） | **+107.2（碾压）** |

净收益从 11 分抬到 107 分，DWB 就**一定会选离墙远的轨迹**，即使因此偏离路径。

### 为什么取 0.5 而不是 1.0

`scale` 太高会让车在**宽走廊**里为了离墙远而主动偏离路径，表现为「沿着一侧墙走」。
本项目走廊有余量，先试 0.5：

- 若仍有爬行 → 上 1.0
- 若出现「贴单侧墙」→ 回退 0.3

这是一个需要实跑对比的取舍，不是纯计算能定的。

### 改动

```yaml
BaseObstacle.scale: 0.5          # 0.1 → 0.5
BaseObstacle.sum_scores: false   # 显式写出来，防止有人默认改 true
```

## 九、教训

1. **`PASS 8 / FAIL 0` 不等于「没问题」。**
   要读每个点的耗时分布。一个点比邻居慢 3 倍，就是有故事。

2. **`progress_checker` 的 allowance 是一个「双职责」参数。**
   它同时管「原地转」和「低速爬行」。拉到 25 s 救了前者、放过了后者。
   真正的解法是**让爬行不要发生**，而不是让判据更严（更严会误杀 shim 的原地转）。

3. **253/254 不是「罚分」，是「淘汰」。**
   `BaseObstacle` 打分用的是 0..252 软代价，且不归一化。
   我 S28 注释里「253 × 0.02 = 5.06 分」这句话是错的，已在本轮修正。

4. **先算账，再改参数。**
   这一轮我算清楚了：降 k 无效（2 cm 带宽）、加 R 被缝 N 卡死、开 sum_scores 帮倒忙。
   **三个方向被排除后，才轮到改 scale**，而不是一上来就调 critic 权重。

5. **参数改动必须带「反向判据」。**
   提高 `BaseObstacle.scale` 的副作用是「贴单侧墙」。
   如果不去观察这个副作用，就等于只验了收益、没验代价。

6. **我自己也踩了工具的坑：**
   一开始用 `rg.inflate_cost(x, y)` 检查 8 个目标点，输出 6 个 254，
   差点去追一个不存在的「目标点在致命格」问题。
   实际是 `inflate_cost(d, radius, inflation, k)`——第二个参数是 `radius`，`y` 落进去了。
   **调用别人的函数前先看签名。**
