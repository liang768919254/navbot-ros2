# S22 复盘：route_loop 回不到起点 —— 不是控制问题，是路线设计问题

日期：2026-11-10
触发：`./drive.py loop` 跑完，用户看到「小车最后停止的位置离原来的位置差距也太大了吧」

---

## 一句话结论

**车走得非常准，是路线本身不闭合。**
旧 `route_loop` 向东只走 2.4 m、向西走 5.0 m，x 方向净差 −2.6 m，
理想情况下终点就是 `(-2.600, -0.200)`，距原点 2.608 m。
实测 `odom = (-2.616, -0.195)` —— 与理论值只差 **1.6 cm / 0.5 cm**。

---

## 证据链

### 1. 车与控制没问题

| 检查项 | 实测 | 结论 |
|---|---|---|
| 直线段误差 | 2.00→1.991 / 2.40→2.394 / 4.00→3.992 / 5.00→4.995 / 2.20→2.195 | 全部 ≤ 0.009 m，优于 tol=0.02 |
| SLAM `map→odom` 平移 | `[0.006, 0.012, -0.000]` | 漂移 ≤ 1.2 cm，定位正常 |
| SLAM `map→odom` 旋转 | `[-0.000, 0.000, -0.005, 1.000]` | yaw 偏差 0.57°，可忽略 |

### 2. 路线从设计上就不回原点

旧路线逐段（理想几何，每步精准）：

```
步   动作            位置(x, y)          朝向
0    起点             ( 0.000,  0.000)     0.0°
1    转向 -90°        ( 0.000,  0.000)   -90.0°
2    直行 2.00m       ( 0.000, -2.000)   -90.0°
3    转向 +90°        ( 0.000, -2.000)     0.0°
4    直行 2.40m       ( 2.400, -2.000)     0.0°     ← 东行只走 2.4
5    转向 +90°        ( 2.400, -2.000)    90.0°
6    直行 4.00m       ( 2.400,  2.000)    90.0°
7    转向 +90°        ( 2.400,  2.000)   180.0°
8    直行 5.00m       (-2.600,  2.000)   180.0°     ← 西行走了 5.0
9    转向 +90°        (-2.600,  2.000)   -90.0°
10   直行 2.20m       (-2.600, -0.200)   -90.0°
→ 终点 (-2.600, -0.200)  距原点 2.608 m  朝向 -90.0°
```

两个独立的设计错误，各自都能单独导致回不去：

1. **x 方向不对称**：东 2.4 vs 西 5.0 → 净差 −2.6 m。
2. **朝向不闭合**：转向序列 −90, +90, +90, +90, +90 → 净 +270°，不是 360°。
   车头最终朝南（−90°），回不到出发时的 +x。

### 3. 转向的「每次少转」是第二个问题，而且确实是 bug

日志：`-89 / +89 / +89 / +89 / +88`，累计 −6°。不像噪声，像系统性提前收。

根因在旧 `turn()`：

```python
if abs(accum) >= abs(angle) - tol:   # tol = 0.03 rad ≈ 1.7°
    break
self.stop()                          # 立刻停，最后一帧角速度还在途
```

⇒ 每次都停在 `angle − 1.7°` 附近，而且**同向累积**（正角少转、负角少转），
不会自相抵消。离线复现（`turn_sim.py`）：单次残差 −0.96°，7 次累计 +4.8°。

## 修复

### `turn()`：收紧判据 + 刹停后再读一次

| | 旧 | 新 |
|---|---|---|
| tol | 0.03 rad (1.72°) | 0.004 rad (0.23°) |
| 收尾 | break 后直接 stop | stop + `_pump(0.25)` 让惯性衰减，再读一次 yaw |
| 速度曲线 | 80% 后降到 0.5ω | 75% 后按比例降到 0.4ω·(remain/25%) |
| 单次残差（离线） | −0.96° | −0.05° |
| 7 次累计（离线） | +4.81° | +0.23° |

### `route_loop()`：对称矩形 + 统一收尾

走廊取值都是被障碍逼出来的，不是随手取的：

| 走廊 | 取值 | 约束 |
|---|---|---|
| 南 | y = −2.05 | `partition_short` 下沿 y=−1.8，净空 0.25；距南墙 0.40 |
| 北 | y = +2.05 | `pillar_a` 上沿 y=+1.65，净空 0.40；距北墙 0.40 |
| 东 | x = +2.50 | 距东墙内表面 2.95，净空 0.45 |
| 西 | x = −2.50 | 同上 |

行程：`南 2.05 → 东 2.50 → 北 4.10 → 西 5.00 → 南 4.10 → 东 2.50 → 北 2.05`
（严格对称，净位移 0；净转 −90 + 90×7 = +540°，由收尾掰回 +x）

### 顺手修掉 `route_survey()`

老 survey 净位移 `(−0.001, +0.688)`，距原点 **0.688 m**，朝向 180° ——
同样是「看着像回到起点，其实差了 0.7 m 还掉了个头」。
新设计：第 1 圈顺时针、第 2 圈逆时针走同一矩形，两圈后都精确回原点。

### 抽公共函数

- `_drive_rectangle(d, reverse=False)` —— 正/反向走同一矩形，两向都验过净空
- `_finish_at_origin(d)` —— 掰正朝向 + 位置闭环（残差 > 5 cm 时调 `route_home`）

为什么还要位置闭环：`turn` 修好后单次 0.05°，但 7~14 次仍会累积 0.5°~1°，
5 m 走廊末端就是几厘米。直接量误差再补，比继续抠开环参数划算。

## 新增的三个验证工具

| 文件 | 作用 | 判据 |
|---|---|---|
| `loop_geom.py` | 逐段打印位置/朝向；`--check` 校核航线净空；`--real` 叠加实测损耗 | 理想终点 < 0.02 m；每段净空 ≥ 0.20 m |
| `turn_sim.py` | 复现 turn 的收敛行为，对比新旧逻辑残差 | 新逻辑残差应 < 旧逻辑 1/3 |
| `selftest_drive.py` | 用假 ROS + 一阶惯性模型跑 turn/straight/route_loop/route_survey | **26 项全 PASS** |

### `selftest_drive.py` 的实测结果

```
[1] turn 单次精度          7 项 PASS   残差均 ±0.05°
[2] turn 7 次累积           PASS       +0.23°
[3] straight 精度          4 项 PASS   误差 ≤ 0.014 m
[4] 新 route_loop 闭环      4 项 PASS   终点 (-0.009, 0.000) 距原点 0.009 m
[4b] survey 两圈            2 项 PASS   第 1 圈 0.009 m / 第 2 圈 0.014 m
[5] 旧路线复现              2 项 PASS   模拟 (-2.601, -0.179) vs 实测 (-2.616, -0.195)
[6] 常量一致性              6 项 PASS   drive 与 loop_geom 走廊常量一致
```

第 [5] 组是关键：用一阶惯性模型独立算出 `(-2.601, -0.179)`，
与真车实测 `(-2.616, -0.195)` 只差 1.5 cm —— 说明「路线设计」这一个因素
就足以解释全部偏差，不需要假设任何控制故障。

## 踩坑记录

### 坑 1：文本替换切错边界，把三个函数一起删了

用 `src[:start] + new + src[end:]` 做批量改写时，`start` 取自
`route_loop` 函数体的第一行、`end` 取自 `def route_survey`。
第二次替换时 `start` 用的是 `route_survey` 里的第一行，
但 `_finish_at_origin` / `route_loop` 的首行匹配文本已被第一次替换改掉，
导致 `index()` 找到的位置把三个函数整段吞掉。

**症状**：`py_compile` 通过（语法没问题），但 `import drive` 后
`AttributeError: module 'drive' has no attribute 'route_loop'`。

**教训**：批量改写之后必须跑一次 `import` + `hasattr` 自检，
`py_compile` 只查语法、查不出「函数被删」。`selftest_drive.py` 的第 [6] 组
就是为这个加的。

### 坑 2：把「偏差大」直接归因于控制，会被数据打脸

第一反应是「转向不准所以漂了」。但一算：
5 次转向各少 1.2°，累积 6°，在 2.6 m 的臂长上只造成 `2.6 × sin6° ≈ 0.27 m`，
**远小于实测 2.6 m**。
⇒ 先算「如果每步都精准，终点在哪」，再谈控制误差。这一步用 `loop_geom.py` 十分钟就能做完。

### 坑 3：`_pump(0.05)` 里只 `spin_once`，不发指令

旧的 `turn` 循环是「publish 一次 → `_pump(0.05)`」，节奏没问题；
但如果把 `publish` 漏在和速度更新同一个缩进层级外，会变成
「只在进循环前发一次」→ 车转一下就停。改这段时务必保持
`publish` 在 `while` 内部。

## 这轮结论的边界

- 离线模型用一阶惯性 `TAU=0.12 s` 拟合，**真实 Gazebo 的阻尼参数未标定**，
  所以「新路线终点 0.009 m」是模型下的值，真车会有出入。
- 只验证了**位置与朝向的数值收敛**，没有验证激光/里程计的噪声耦合。
  真车跑完请看 `_finish_at_origin` 打印的「开环收尾位姿」那一行，
  那个才是最终判据。
- `route_home` 本身不做避障，只在残差小、路径无障碍时用。若收尾时
  残差 > 0.5 m，应重启 Gazebo 而不是靠 `route_home` 硬拉。
