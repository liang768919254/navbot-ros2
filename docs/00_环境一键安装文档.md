# ROS2 Humble 自主导航移动机器人 —— 环境一键安装文档

> **适用环境**：Ubuntu 22.04 LTS（Jammy）
> **目标栈**：ROS2 Humble + Gazebo Classic 11 + Nav2 + slam_toolbox
> **用途**：换新机器 / 重装系统后，按本文档从上往下跑一遍，即可还原完整开发环境。
> **验证基准**：本文档按本项目 `P3_ROS2自主导航移动机器人_保姆级项目文档.md` 实测环境（328 个 ROS 包）整理。

## 1. 一键安装脚本（完整版）

> 直接整段复制到终端执行。已装过的包 apt 会自动跳过，重复执行无副作用。
> fishros 那一步需要交互，**请选 desktop 版**（不要选 base，否则没有 rviz2）。

```bash
#!/usr/bin/env bash
set -e

# ============ 阶段 0：基础工具 ============
sudo apt update
sudo apt install -y \
  build-essential git cmake curl wget \
  python3-pip python3-argcomplete

# ============ 阶段 1：ROS2 Humble（fishros 一键，选 desktop）============
wget http://fishros.com/install -O fishros && . fishros

# ============ 阶段 2：构建与依赖工具链 ============
sudo apt install -y \
  python3-colcon-common-extensions \
  python3-rosdep \
  python3-vcstool

# ---- rosdep 初始化 + 国内镜像加速 ----
# ★ 国内必做：raw.githubusercontent.com 连不上，rosdistro 索引走中科大镜像
sudo rosdep init || true          # 已 init 过会报 "already exists"，忽略即可
sudo rosdep fix-permissions       # 若之前用 sudo 跑过 update，先修权限
export ROSDISTRO_INDEX_URL=https://mirrors.ustc.edu.cn/rosdistro/index-v4.yaml
echo 'export ROSDISTRO_INDEX_URL=https://mirrors.ustc.edu.cn/rosdistro/index-v4.yaml' >> ~/.bashrc
rosdep update                     # ★ 不加 sudo，普通用户跑

# ============ 阶段 3：机器人建模与状态发布 ============
sudo apt install -y \
  ros-humble-xacro \
  ros-humble-urdf \
  ros-humble-robot-state-publisher \
  ros-humble-joint-state-publisher \
  ros-humble-joint-state-publisher-gui \
  ros-humble-tf2-tools \
  ros-humble-rviz2

# ============ 阶段 4：Nav2 完整导航栈 ============
# navigation2 是总元包，会连带 amcl / dwb-controller / navfn-planner / map_server 等
sudo apt install -y \
  ros-humble-navigation2 \
  ros-humble-nav2-bringup \
  ros-humble-nav2-rviz-plugins \
  ros-humble-nav2-simple-commander

# ============ 阶段 5：SLAM ============
sudo apt install -y ros-humble-slam-toolbox

# ============ 阶段 6：Gazebo Classic 仿真 ============
# ★ 注意：装的是 Classic 11，不是 Ignition/Garden（那个是 ros-humble-ros-gz）
sudo apt install -y \
  gazebo \
  ros-humble-gazebo-ros-pkgs

# ============ 阶段 7：运动控制与多源仲裁 ============
sudo apt install -y \
  ros-humble-twist-mux \
  ros-humble-teleop-twist-keyboard

# ============ 阶段 8：定位与传感器（真机用，无硬件可先跳过）============
sudo apt install -y \
  ros-humble-robot-localization \
  ros-humble-rplidar-ros

# ============ 阶段 9：串口 / 无硬件自测工具链 ============
# ★ pyserial 必须用 apt 的 python3-serial，不要用 pip install pyserial
sudo apt install -y \
  socat \
  python3-serial

# ============ 阶段 10：可选参考（备用）============
sudo apt install -y \
  ros-humble-turtlebot3-gazebo \
  ros-humble-urdf-tutorial

echo "===== 全部安装完成 ====="
```

## 4. 常见坑（本项目的踩坑记录）

1. **Gazebo 版本**：Humble 对应 **Gazebo Classic 11**，包名就是 `gazebo`。不要装 `ros-humble-ros-gz`（那是新 Gazebo Ignition/Garden 的桥接），否则 `navbot.gazebo.xacro` 里 `<gazebo>` 标签的插件会找不到。

2. **pyserial 必须用 apt**：`sudo apt install python3-serial`，**不要** `pip install pyserial`。本项目 `fake_chassis.py` 用的是系统 python（`/usr/bin/python3`），pip 装的环境不一定是系统环境。

3. **fishros 选 desktop**：选 base 版会缺 rviz2、turtlebot3 演示等，导航项目用 desktop 省事。

4. **`source setup.bash` 在 `set -u` 脚本里报错**：`/opt/ros/humble/setup.bash` 内部引用了未定义变量（`AMENT_TRACE_SETUP_FILES` 等），在 `set -u` 下 source 会报 `未绑定的变量`。解法是 source 前后临时 `set +u` / `set -u`（本项目 `verify_e2e.sh` 就是这么处理的）。

5. **虚拟串口依赖 pty**：`socat pty` 依赖 `/dev/ptmx` 和 `/dev/pts`，容器/部分 WSL/安全沙箱里会缺，报 `openpty(...): No such file or directory`。本项目脚本已内置 TCP 回环降级路径，真机 Ubuntu 双系统上不会遇到。

6. **rosdep 未 init**：`colcon build` 若报 rosdep 相关错误，先 `sudo rosdep init && rosdep update`。

7. **`rosdep update` 卡在 `raw.githubusercontent.com` 超时**：国内连不上，报 `error loading sources list: The read operation timed out`（本坑已实测复现，raw 返回 000）。解法是让 rosdistro 索引走中科大镜像：
   ```bash
   export ROSDISTRO_INDEX_URL=https://mirrors.ustc.edu.cn/rosdistro/index-v4.yaml
   rosdep update
   ```
   并写入 `~/.bashrc` 持久化（下次换环境也不用再设）。两点注意：
   - `20-default.list already exists` 不是错误，说明 `rosdep init` 已做过，跳过即可；
   - 若之前用 `sudo rosdep update` 跑过（提示 `running as root is not recommended`），先 `sudo rosdep fix-permissions`，再用**普通用户**（不加 sudo）跑 `rosdep update`。

8. **`colcon build` 报 `find_package(joint_state_publisher)` 找不到 Config.cmake**：`joint_state_publisher` 是**纯 Python 包**（ament_python），不提供 `joint_state_publisherConfig.cmake`，所以在 ament_cmake 包里的 `find_package(joint_state_publisher REQUIRED)` 必然失败（本坑已实测复现）。报错形如：
   ```
   Could not find a package configuration file provided by "joint_state_publisher"
   ```
   解法：把 `joint_state_publisher`（以及 `robot_state_publisher`）从**编译依赖**降为**运行时依赖**：
   - `CMakeLists.txt` 删掉 `find_package(joint_state_publisher REQUIRED)`（`robot_state_publisher` 同理可删）；
   - `package.xml` 把 `<depend>` 改成 `<exec_depend>`。
   
   根因是 `ros2 pkg create --dependencies ... joint_state_publisher` 把运行时依赖写进了 `--dependencies`，导致生成了错误的 `find_package`。正确做法：`--dependencies` 只放有 Config.cmake 的包（urdf/xacro），运行时用的节点（joint_state_publisher / robot_state_publisher）放到 `<exec_depend>`。
